# T001 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the typed, validated Rust domain foundation for OpenECU without proprietary assets or live ECU access.

**Architecture:** A Cargo workspace exposes six independent domain crates. `openecu-definitions` owns the versioned `.oedef` interchange model; calibration, firmware, solutions, and communication each expose pure contracts. The dependency graph keeps calibration independent of communication.

**Tech Stack:** Rust stable, Serde/serde_json for JSON, thiserror for domain errors, GitHub Actions.

**Spec:** User-approved T001 architecture in this conversation.

## Global Constraints

- Work only in this OpenECU repository; do not change `LICENSE`.
- Do not add proprietary firmware/DAMOS assets or real ECU communication.
- Keep calibration free of communication dependencies.
- Do not commit or push.

## Review Focus

- Empty ECU identity fields must fail validation.
- Definitions with an unsupported schema version must fail rather than being accepted silently.
- Calibration data must reject ragged matrices and axes that do not match the declared dimensions.
- Firmware byte windows outside the image bounds must be rejected.
- A controlled modification must require a non-empty rationale and a known target.
